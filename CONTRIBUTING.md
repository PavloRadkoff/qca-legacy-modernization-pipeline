# Contributing to QCA Framework

Welcome to the Research Lab. Given the proprietary and architectural nature of the **QCA (Quantitative Code Analysis)** project, we have a specific process for contributions.

## 🔬 Research & Feedback
We highly value academic feedback and architectural discussions. If you have identified a pattern or have a suggestion:
1. Open an **Issue** to discuss the architectural concept.
2. For deep technical discussions, please reference the specific Whitepaper number.

## 🛠 Pull Requests (PRs)
- Direct PRs that modify the core QCA logic or Whitepapers will not be merged without prior discussion.
- If you wish to contribute an AST parser for a specific legacy language (e.g., COBOL, FoxPro, old PL/I), please contact the author first to align with the framework's deterministic standards.

## 💼 Business & Enterprise Inquiries
If you represent an organization looking to apply QCA for commercial modernization:
- **Do not** submit internal corporate code via PRs or Issues.
- Contact **Pavlo Radko (Radkoff)** directly to discuss a secure, on-premise PoC (Proof of Concept) under a Non-Disclosure Agreement (NDA).

*Legacy is a resource. Let's modernize it with discipline.*
